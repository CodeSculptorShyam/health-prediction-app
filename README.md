# Health Prediction Application

A small Flask + SQLite application demonstrating patient-record CRUD operations,
server-side validation, a REST API, and optional AI-generated educational remarks.

## Features

- Create, view, update, and delete patient records.
- Validate email addresses, dates of birth, and numeric blood-test values.
- Store records persistently in SQLite.
- Generate cautious, non-diagnostic remarks through the OpenAI API.
- Continue saving records when the AI API is not configured or unavailable.
- Expose REST endpoints for patient CRUD operations.

## Requirements

- Python 3.10 or newer recommended
- An OpenAI API key for live AI-generated remarks (optional for basic CRUD testing)

## Setup (Windows)

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Edit `.env` locally and add your API key and a random Flask secret key.
Never commit `.env` or share your API key.

Run:

```powershell
python app.py
```

Open http://127.0.0.1:5000/

## REST endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/patients` | List all patients |
| POST | `/api/patients` | Create a patient |
| GET | `/api/patients/<id>` | Get one patient |
| PUT | `/api/patients/<id>` | Update a patient |
| DELETE | `/api/patients/<id>` | Delete a patient |

POST and PUT endpoints accept a JSON object with `full_name`, `dob`, `email`,
`glucose`, `haemoglobin`, and `cholesterol`. Remarks are generated by the backend.

## Validation

The application accepts dates in `dd/mm/yyyy` or `dd.mm.yyyy` notation to support
the assignment's supplied data. Valid dates are stored as `dd/mm/yyyy`.
Impossible and future dates are rejected. Email format is checked server-side.
Blood test fields must be finite positive numbers no greater than 100000.

## AI and medical safety

The AI service receives blood test values only; it does not receive patient names
or email addresses. The app does not diagnose disease. Units, lab reference ranges,
fasting status, and clinical context are not supplied, so remarks must be treated
as general education only. Consult a qualified healthcare professional.

If the API is unconfigured or unavailable, the record can still be saved and the
Remarks field explains that AI output is unavailable.

## Security notes

- `.env` and `patients.db` are excluded by `.gitignore`.
- Set `FLASK_SECRET_KEY` before using outside local development.
- Flask debug mode is enabled only for local development; disable it in deployment.
- This is an evaluation/demo application, not a production clinical system.
- Use synthetic or approved test data only; avoid uploading real patient information.
